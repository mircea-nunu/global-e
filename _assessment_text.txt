1. Background
You are given a raw JSON export from a retail company's ERP system. The file (orders_raw.json) contains 12 sales orders with nested customer info, line items, and shipping details.

Your job is to engineer this data end-to-end: extract and flatten it, load it into a structured target model, and design the reporting layer that a dashboard would sit on top of.

2. The Tasks
Complete all three tasks. They build on each other.

Task 1: Extract &amp; Load
Parse orders_raw.json and extract all orders and their line items.
Load the data into two target tables (your choice of storage — DB, CSV, DataFrame):
  •  orders  — one row per order (id, date, status, channel, customer info, sales rep, shipping cost)
  •  order_lines  — one row per line item
For each line item in order_lines, calculate and store:
  •  line_revenue_local  = quantity × unit_price × (1 – discount_pct / 100)  [in original currency]
  •  line_revenue_usd    = line_revenue_local converted to USD
       Use a fixed rate: 1 EUR = 1.08 USD. Store the currency and rate used.
  •  Include order_id as a foreign key back to orders
Data quality: Before loading, scan the source data and document at least 2 data quality
issues you find. For each issue, state: what it is, which records are affected,
and how you handled it in your pipeline.
Handle edge cases: cancelled orders, null values, and orders with no discount.

Task 2: Data Model
Design a star-schema data model suitable for reporting.
Your model should include:
  •  A central fact table (fact_sales) at line-item grain
  •  At least 3 dimension tables: Customer, Product, Date — plus any others you see fit
  •  All amounts in USD (use line_revenue_usd)
Deliverable: A diagram showing table names, key columns, and PK/FK relationships.
(draw.io, dbdiagram.io, Lucidchart, hand-drawn photo — anything is fine)
Answer these two design questions in your README (3–5 sentences total):
  Q-A: CUST-1042 'Sarah Mitchell' appears in 3 orders. Look carefully at her data
       across those orders — something changes. How would you handle this in your model,
       and what are the trade-offs of your approach?
  Q-B: If this JSON file were delivered daily with new orders appended,
       how would you change your pipeline to load only new records?

Task 3: Reporting Layer
Write 4 SQL queries (or DAX / calculated fields) that a dashboard would use.
All revenue figures should use line_revenue_usd.
  Q1 — Monthly revenue trend (Delivered orders only)
  Q2 — Top products by total USD revenue, with each product's % share of total
  Q3 — Revenue by customer segment and channel
  Q4 — For each customer, show: total orders, total USD revenue, and revenue rank
        among all customers  (hint: a window function is the clean way to do this)
Create a simple dashboard or mock-up showing these KPIs visually.
Bonus (optional): Write a short dbt model (or equivalent) for fact_sales.
